# 에셋별 비교(scissor) + 조건 프리셋 설계

> 2026-08-05. 잡 간(에셋별) 메쉬 비교를 brain-educate ch4식 2-창 scissor 뷰로
> 추가하고, 조건 프리셋(노화/치매/알콜)으로 관련 영역만 골라 메쉬 품질을
> 확인한다. 기존 잡 내 pan-row 뷰어와 **공존**(모드 전환). 전부 프론트엔드 —
> 백엔드 변경 없음.

## 1. 목적과 범위

기존 뷰어는 **한 잡의 변형들**을 pan-row로 나란히 본다(메쉬 생성옵션 품질 비교,
주기능). 이 설계가 더하는 것:

1. **에셋별 비교 모드(scissor)** — 서로 다른 잡의 산출물을 좌/우 2창으로 놓고
   동기 회전하며 비교. 잡 간 비교는 부가기능(스펙: mesh-option-compare Phase C).
2. **조건 프리셋** — 노화/치매/알콜 각 조건의 관련 영역만 원색 불투명으로 남기고
   나머지는 투명하게 해, 그 영역들의 메쉬 품질을 맥락과 함께 확인. 두 모드 공통.
3. **크기 정규화 토글**(비교 모드 전용) — 사람마다 뇌 크기가 다르므로, 켜면 두
   창을 공통 크기로 스케일. 토글해 "정규화가 형상을 얼마나 바꾸나"를 확인.

### 비목표
- 백엔드/엔드포인트 추가(기존 `listJobs`·`getStatus`·GLB/meta로 충분).
- 3창 이상(딱 2창).
- pan-row(잡 내, 같은 사람) 정규화 — 같은 해부구조라 불필요.
- brain-educate식 무채색 반투명(여기 목적은 질병 시각화가 아니라 메쉬 QA라 원색 유지).

## 2. 전역 제약

- 완전 로컬 · 외부 통신 0. `esc()`로 렌더 값 이스케이프 유지.
- world-mm 공유 스케일이 기본(정규화 OFF) — 실제 크기 차이를 그대로 보여준다.
- 프리셋 영역 세트는 `labels/canonical-v1.tsv`의 영역명을 기준으로 한다(존재하는
  이름만). brain-educate ch4/ch5 세트와 대조해 확정.

## 3. 뷰어 두 모드 (공존)

사이드바에 **모드 토글**을 둔다.

- **기본 모드**(현행): 잡 하나 선택 → 그 잡의 변형들 pan-row + 생성 폼(옵션·큐·
  변형 생성)·범례·표기 컨트롤. 변경 없음.
- **에셋별 비교 모드**(신규): 사이드바 "에셋별 비교" 진입 버튼으로 전환. 캔버스가
  2열 scissor로 바뀌고, 옆 패널은 **생성 UI를 숨기고 표기 컨트롤만** 보인다.

모드 전환 시 뷰어를 정리(dispose)하고 해당 모드로 다시 그린다.

## 4. 에셋별 비교 모드 (scissor)

### 4.1 렌더링
- **renderer 1개 + scene·camera 2개.** `renderer.setScissorTest(true)` + 창별
  `setViewport`/`setScissor`로 캔버스를 좌/우 반씩 그린다(브레인에듀케이트
  DualBrain3D와 동일 구조).
- **동기 회전.** OrbitControls를 좌 카메라에 바인딩, 매 프레임 우 카메라에
  `position`·`quaternion`·`zoom`을 복사. 한 드래그로 두 창 동시 회전.
- 각 창의 GLB는 자기 bbox 중심으로 원점 정렬 + 업라이트 회전(-90° about X)·스무스
  노멀(기존 로직 재사용).

### 4.2 창 선택 (드롭다운 2단)
- 각 창 상단에 드롭다운 둘: **잡 선택**(`listJobs`) → **변형 선택**(그 잡의
  `getStatus(jobId).variants`). 좌우 독립.
- 선택 시 해당 창의 GLB/meta를 로드해 그 창의 scene을 교체(다른 창은 유지).
- 빈 창(미선택)은 아무것도 안 그린다.

### 4.3 크기 정규화 토글
- 캔버스 상단 **가운데(분할선 위)** 플로팅 토글.
- **OFF(기본)**: world-mm 원본 배치 → 실제 뇌 크기 차이 그대로.
- **ON**: 각 창 그룹을 공통 목표 크기로 스케일(그룹 bbox 최대변 → 공통 상수).
  두 창이 같은 화면 크기로 맞춰져 형상·메쉬만 비교.
- 토글 시 양쪽 스케일 재적용 + 카메라 리프레임.

## 5. 조건 프리셋

### 5.1 데이터 (`mri2mesh/web/static/condition-presets.json`, 신규)
- 조건 → 영역명 집합을 **정적 JSON** 한 파일에 둔다(단일 원천 — 프론트가 fetch로
  읽고, 파이썬 테스트가 같은 파일을 읽어 canonical-v1과 대조):
  ```json
  {
    "노화": ["<canonical-v1 영역명>", "..."],
    "치매": ["..."],
    "알콜": ["..."]
  }
  ```
- 영역명은 `labels/canonical-v1.tsv`에 **실재하는 이름만**(구현 시 tsv·brain-educate
  ch4/ch5 세트와 대조해 채운다). 매칭은 meta.regions의 영역 식별자 기준.
- `presets.js`(신규)는 이 JSON을 fetch해 5.2 적용 헬퍼를 제공한다.

### 5.2 동작
- 표기 컨트롤에 프리셋 선택(없음/노화/치매/알콜).
- 선택 → 프리셋 영역은 **원색 불투명**, 비프리셋 영역은 **투명**(opacity 낮게,
  depthWrite off). "없음"이면 전체 원색 불투명.
- 기존 반투명 셸 + 영역 가시성 메커니즘을 재활용 — 프리셋이 영역 집합을 자동
  세팅한다. 두 모드 공통, 비교 모드에선 두 창 동시 적용.

## 6. 파일 구조

- `mri2mesh/web/static/viewer.js` — 비교(scissor) 모드 추가: 2 scene/camera,
  setScissor 렌더, 동기 회전, 창별 로드/교체, 정규화 스케일. 기존 pan-row 경로는
  유지하고 모드 분기.
- `mri2mesh/web/static/condition-presets.json` (신규) — 조건→영역명 세트(단일 원천).
- `mri2mesh/web/static/presets.js` (신규) — JSON fetch + 적용 헬퍼.
- `mri2mesh/web/static/app.js` — 사이드바 모드 토글, 비교 모드 진입 시 vpanel에서
  생성 UI 숨김·표기 컨트롤만, 좌우 드롭다운(잡→변형), 정규화 토글, 프리셋 선택 배선.
- `mri2mesh/web/static/index.html` — 모드 토글·2창 드롭다운 자리·정규화 토글·프리셋
  셀렉트 + 스타일.
- 테스트: 파이썬 단위 테스트가 `condition-presets.json`을 읽어 **모든 프리셋 영역명이
  `labels/canonical-v1.tsv`에 실재하는지** 검증(오탈자·이름 불일치 방지). 뷰어 자체는
  JS 단위 테스트 없음 — 수동 확인.

## 7. 흐름 요약

```
사이드바 모드 토글
  ├─ 기본: 잡 선택 → pan-row 변형 뷰 + 생성 폼 (현행)
  └─ 에셋별 비교: 2열 scissor
       좌 드롭다운(잡→변형) / 우 드롭다운(잡→변형)
       동기 회전, 가운데 정규화 토글(OFF=실제크기 / ON=공통크기)
       표기 컨트롤(반투명·빅뱅·영역·프리셋) 두 창 동시 적용
조건 프리셋: 영역 집합 자동 세팅 → 프리셋 영역 원색 불투명, 나머지 투명
```
